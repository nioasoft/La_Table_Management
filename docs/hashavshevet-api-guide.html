1. בקצרה

  • H-Connect הוא ה-API הרשמי של חשבשבת H-ERP. עובד רק מגרסה SP3 2022 ומעלה.
  • Endpoint אחד: POST https://ws.wizground.com/api, גוף JSON. השרת של חשבשבת (wizground) הוא מתווך: הוא מעביר את הבקשה לתוסף שמותקן על שרת ה-SQL של הלקוח.
  • כל בקשה מזוהה ע"י station (התחנה של הלקוח), company (קובץ החברה), plugin (סוג הממשק) ו-netPassportID (מזהה בית התוכנה, כלומר אנחנו), וחתומה ב-md5(JSON(pluginData) + token).
  • ייבוא לחשבשבת לא נכתב ישר ל-DB. הנתונים נוחתים כקובץ .dat בתיקייה C:\hash7\Hconnect\ אצל הלקוח, ומסופון 2 (Masofon2) קולט אותם לחשבשבת לפי קובץ אצווה (batch) מוגדר מראש. זה מסלול הקליטה היחיד.
  • ייצוא מחשבשבת נעשה דרך דוח שבונים במחולל הדוחות של חשבשבת, מצפינים בכלי Hrep, ושולחים את המחרוזת המוצפנת לפלאגין reports.
  • הפלאגין שרלוונטי לנו הוא movein (פקודות יומן). ייצוא האקסל "ייבוא חשבשבת" שאנחנו כבר מפיקים הוא בדיוק המבנה הזה, עמודה אחרי עמודה (ראו סעיף 12).

3. מה חשוב לדעת לפני שמתחילים

‏status: ok לא אומר שהנתונים בחשבשבת. התשובה רק מאשרת שהקובץ נכתב לתחנה. הקליטה בפועל קורית במסופון 2, שיכול להיכשל בגלל חשבון שלא קיים, תנועה לא מאוזנת וכו'. השגיאות נכתבות למחיצת יומן שגיאות (ברירת מחדל C:\Hash7\rep\Err), ואפשר להגדיר שליחה שלהן במייל. ה-API עצמו לא מחזיר אותן. לכן צריך להחליט מי מריץ את מסופון 2 (ידנית או מתוזמן), ואיך אנחנו יודעים שהקליטה הצליחה. הכי סביר: דוח reports שבודק שהאסמכתאות נקלטו.
החתימה תלויה בבייטים המדויקים. מחשבים md5 על JSON.stringify(pluginData) ומשרשרים את הטוקן. השרת מחשב אותו דבר בצד שלו, אז ה-pluginData שבגוף הבקשה חייב להיות זהה תו-לתו למחרוזת שנחתמה: אותו סדר מפתחות, בלי רווחים, אותו escaping לעברית. כל הבדל מחזיר netPassportError.
מגבלת גודל: 4MB לבקשה. פקודות יומן של חודש שלם לכל הזכיינים עוברות את זה בקלות, אז צריך לפצל לכמה בקשות.
קובץ batch לכל צירוף. שם הקובץ במסופון 2 הוא compId_plugin_netPassportID (בצילום: 1_movein_250075.bat). לכל חברה × ממשק צריך batch משלו, ואם הוא חסר מקבלים שגיאה 14 (Batch file doesn't exist).
טוקן. נוצר בחשבשבת ב"הגדרות H-Connect" לכל שורה (חברה × ספק × ממשק). לפי התיעוד, לאותו שם ספק הטוקן זהה בכל הממשקים והחברות. זה סוד, ושומרים אותו ב-env בלבד.
תאריכים. בדוגמאות של הייבוא הפורמט הוא dd/mm/yyyy ("10/02/2023"), אבל פרמטרי תאריך בדוחות (reports) הם mm/dd/yy. וכרגיל אצלנו: לעולם לא toISOString().
כל הערכים נשלחים כמחרוזות. בכל הדוגמאות גם סכומים ומספרים הם strings ("5.00"). זה קריטי למספר הקצאה: הוא יכול להתחיל ב-0 (למשל 091097208), אז שולחים אותו כ-string ולעולם לא כ-number.
מפתח חשבון ספרתי. אם אינדקס החשבונות בחברה ספרתי, אורך המפתח בקובץ חייב להיות זהה לאורך שהוגדר בחברה (movein).
אין סביבת sandbox ציבורית. חשבשבת ממליצה לבית התוכנה להתקין סביבת פיתוח על שרת או עמדה מקומית משלו (בחינם), ולהתחבר ל-Production רק בסוף. כל תמיכה בתשלום (ראו סעיף 4).

7. חתימה (signature)

signature = md5( JSON.stringify(pluginData) + token ), בפלט hex באותיות קטנות. בלי רווחים במחרוזת. בתיעוד יש גם דוגמה ישנה עם חתימה בסגנון JWT (מנגנון net-passport קודם). להתעלם ממנה.

בגרסת TypeScript שלנו לא צריך תלות חיצונית. חותמים ושולחים את אותה מחרוזת:

import { createHash } from "node:crypto";

/** Builds a signed H-Connect request body. The pluginData string is signed and sent verbatim. */
export function buildHConnectBody(plugin: string, pluginData: unknown) {
  const token = process.env.HCONNECT_TOKEN!;          // never hardcode
  const data = JSON.stringify(pluginData);
  const signature = createHash("md5").update(data + token, "utf8").digest("hex");
  // Splice the exact signed string into the body so re-serialization can't drift.
  return `{"station":${JSON.stringify(process.env.HCONNECT_STATION)},` +
         `"plugin":${JSON.stringify(plugin)},` +
         `"company":${JSON.stringify(process.env.HCONNECT_COMPANY)},` +
         `"message":{"netPassportID":${JSON.stringify(process.env.HCONNECT_PASSPORT_ID)},"pluginData":${data}},` +
         `"signature":"${signature}"}`;
}

הערה: בדוגמה של התיעוד הם מעבירים אובייקט ל-axios ונותנים לו לסדר אותו מחדש. ב-JS זה עובד, כי סדר המפתחות נשמר וגם axios משתמש ב-JSON.stringify. אבל שזירת המחרוזת שנחתמה ישירות לגוף הבקשה מבטלת את הסיכון לגמרי. במקור לא נאמר במפורש ש-md5 מחושב על UTF-8. זו הנחה סבירה ל-Node, וצריך לבדוק אותה מול עברית בבקשת הבדיקה הראשונה.

8. הגדרות בתוך חשבשבת (צד הלקוח)

  4. מסופון 2: מגדירים batch לכל שורה כזו (סעיף 9).

  1. מורידים את report-list.zip (בתוכו קובץ ‎.rpx בשם "רשימת דוחות"), שומרים ב-C:\hash7, ומייבאים אותו בדוחות ← מחולל דוחות. מתקבל דוח "רשימת דוחות במחולל", שבו מוצאים את ה-ID של הדוח הרצוי.

שורה תחתונה: הכי קל להתחיל רק עם movein לפקודות היומן, כי המבנה כבר קיים ונבדק מול רעות. צריך רק לבנות מסלול שליחה במקום הורדת אקסל, ובעתיד דוח reports שמאשר שהקליטה הצליחה.

14. סתירות וחורים בתיעוד

  • גרסה: במבוא כתוב "SP3 2022", ובדרישות "מהדורה 2a SP2022".
  • דוגמת החתימה בעמוד "מבוא לייבוא" היא JWT (מנגנון net-passport ישן), וה-JSON שם שבור. המנגנון הנוכחי הוא md5 (עמוד "בקשת ה-API").
  • עמוד מבוא ליצוא מציג קוד עם require("net-passport") ו-netPassport-win.exe על פורט 8040. גם זה כנראה שריד מהמנגנון הקודם.
  • אותיות גדולות וקטנות בשמות שדות לא עקביות: בטבלה Reference/SuFDeb1, ובדוגמה reference/SufDeb1. כנראה לא case-sensitive, צריך לבדוק.
  • movein: התוויות של ValueDate ("date אסמכתא") ו-DueDate ("date ערך") לא ברורות. TaxAPINumber מוגדר Numeric(250), ובפועל חייב להיות string.
  • imovein: השדה 2Address בטבלה מופיע כ-Address2 בדוגמה. בדוגמת JSON כל הבקשה עטופה במערך [...], כנראה טעות.
  • stockheaderin: הקישור "להורדת קובץ prm" לא מוביל לשום מקום.
  • אין תיעוד לתשובות שגיאה (status code, מבנה JSON), אלא רק טקסטים. אין תיעוד ל-rate limit, ל-timeout או ל-idempotency.
  • אין תיעוד למבנה התשובה של reports, getPDF ו-ExPIc.

מה זה H-Connect?

מערכת H-Connect היא ממשק API שמסייע לחבר בין מערכת חשבשבת H-ERP למערכות יעודיות אחרות הקיימות בעסק שלכם. הפעלת המערכת פשוטה וחוסכת זמן עבודה של המתכנתים שלכם.

שימו לב

העבודה עם H-Connect אפשרית רק מגרסא SP3 2022 ומעלה של חשבשבת

מה זה API?

API הם ראשי תיבות של Application Programming Interface או בעברית ממשק תכנות יישומים.
הממשק כולל ספריות קוד פתוח, תקשורת נתונים ועוד, באמצעותן ניתן למשוך מידע או להתחבר למאגר מידע ונתונים של חברה אחרת.
חשבשבת H-ERP מאפשרת את החיבור אל מסד הנתונים שלה, על ידי קוד פתוח זה. הממשק מלווה במידע מפורט המסביר את אופן השימוש בקוד, כך שהמתכנתים העוסקים בחיבור בין המערכות יכולים לעשות זאת בקלות ולחסוך זמן עבודה יקר.

איך עובד הAPI של חשבשבת?

תוכנת חשבשבת עובדת עם שרת MS SQL server המותקן אצל הלקוח. ההתקנה מתבצעת במחשב/שרת מקומי, או בשרת בענן. ה-API איננו מתקשר ישירות עם שרת הלקוח, אלא עם שרת ייעודי של חברת חשבשבת.

בדיקות מיוחדות והערות

  1. מפתח חשבון ומפתח פריט שונים מאפס.
  2. האם שדות אסמכתא, סוכן, מחסנים ומספר עותקים הם מספר חיובי ושונה מאפס.
  3. כמות שונה מאפס.
  4. מחיר חייב להיות חיובי.
  5. באם קיים מטבע האם המטבע קיים בחברה שבה קולטים את הממשק.
  6. תאריכים שגויים.
  7. אחוזי הנחה (בשורה וכללית) חייבים להיות בין % 100- (מינוס 100) ל 100%.
  8. אחוז עמלה ואחוז מס קניה חייבים להיות בין 0% ל- 100%.
  9. באם לא מסומן 'להקים חשבונות/פריטים חדשים' האם החשבונות/פריטים קיימים באינדקס.
  10. אורך שדות. עבור שדות ארוכים מהמותר תופיע הודעת שגיאה. לדוגמה, שדה עוסק מורשה מוגבל ל- 9 תווים.
  11. לא ניתן לקלוט מסמכי יבוא ויצוא ללא מטבע ושער. כמו כן, מטבע המסמך לא יכול להיות זהה למטבע המוביל בחברה.
  12. כאשר נרצה להתייחס למחירים לפי החשבשבת, יש לסמן שליפת מחירים בהגדרות הכלליות במסופון2.
    במקרה זה לא נשלח מחיר בבקשת הJSON
  13. אם בקובץ הממשק לא מעבירים שדה תאריך או שדה תאריך ערך, ברירת המחדל תהיה תאריך המערכת במחשב בעת קליטת הממשק בחשבשבת.

  • שדה מטבע מוביל בקבלה קובע האם זו קבלה בשקלים או קבלה במט"ח.

  • אם לא מעבירים שדה מטבע מוביל בקבלה – ברירת המחדל היא שקל.

  • אם לא מועבר מטבע שערוך, ברירת המחדל היא מטבע מוביל לשערוך כפי שנרשם בהגדרות חברה.

  • אם מטבע הקבלה הוא מט"ח סכום התנועה נרשם בשדה סכום מט"ח. אפשר לשערך את הסכום במט"ח לשקלים ולרשום את הסכום המשוערך בשדה סכום בשקלים. אין צורך לרשום את מטבע השערוך בתנועה.

מכיוון שניהול הלקוח מתבצע בחשבשבת (ניהול האובליגו והאשראי), יש חשיבות להקמת כרטיסי הלקוחות בחשבשבת ובסנכרון חד כיווני לאתר.

סנכרון כרטיסי פריטים

הפריטים מוקמים בחשבשבת. חשוב מאד לנצל את האפשרויות בתוכנה לניהול מלאי מוקפד, וליצירת הזמנות רכש, תוך שימוש בכלים המתקדמים לתכנון הרכש והאופטימיזציה של המלאי. סנכרון הפריטים מתבצע בתדירות הרצויה, פעם בלילה או מספר פעמים ביום. הסנכרון הוא חד כיווני לאתר האינטרנט. דוח הפריטים יכיל את הפריטים הקיימים באתר וכן את המלאי הזמין למכירה באתר.
מהו מלאי זמין?
מלאי זמין מתייחס ליתרת הפריט ממחסן האתר, אחרי גריעת צבר ההזמנות. ניתן לרשום בשדה נתון נוסף בפריט כמות מינימום, ולהתחשב בנתון זה בנוסחה לחישוב המלאי הזמין.

סנכרון מחירונים

חשבשבת מאפשרת לקבוע מחירים ללקוחות בדרכים מגוונות. לדוגמא, ניתן לקבוע מחיר לפי כמות, או להחיל על המחיר מבצע כלשהו. יש להעביר את המחירון הרלוונטי מהמשרד האחורי לאתר, ולוודא שבקבוצת הפריטים הנמכרים באתר, אין משתמשים במשרד האחורי במחירים תחת תנאים מורכבים (שאם לא כן, המחיר באתר עלול להיות שונה מהמחיר במשרד האחורי)
יש לוודא שמחיר המכירה העובר לאתר אינו כולל מע"מ, וגם הממשק החוזר אינו כולל מע"מ במחיר. על אף זאת, חובה להציג באתר קמעונאי את המחיר הכולל מע"מ

ממשק הזמנות

הזמנות מלקוחות מתקבלות בערוצים השונים: בהקלדה משיחת טלפון, באמצעות מסופוני סוכנים, מאתרי סחר וגם מאתר האינטרנט. כדאי לסמן את ההזמנות מהאתר כדי שניתן יהיה לפלח את ההזמנות לפי ערוצים השונים.
קיימות שתי אפשריות לקליטת הזמנות: למאגר זמני או למאגר קבוע.
אם ההזמנות המקוריות הופקו באמצעות תוכנה אחרת (או בפנקס ידני) יש לקלוט את ההזמנות באמצעות המסמך הזמנת סוכן. ההזמנה צריכה לכלול את נתוני המוצרים (פריטים) כמויות, מחירים (ללא מע"מ), סוג משלוח, פרטי הלקוח, הערות וכו'.

ממשק קבלות

אחד הנושאים הקריטיים בניהול אתר אינטרנט המבצע סליקה של כרטיס אשראי הוא הפקת קבלות. לפי הוראות רשות המסים יש להפיק קבלה מיד עם סליקת כרטיס האשראי. חשבשבת מאפשרת קליטה של הקבלה ממערכת הסליקה החיצונית ושליחת הקבלה ללקוח במייל. נתוני התשלום ייקלטו במאגר זמני של הקבלות, ועל המשתמש להפיק את הקבלה (או מספר קבלות ברצף) באופן יזום. הקבלות יופקו ויישלחו למייל אותו רשם הלקוח כאשר ביצע את ההזמנה באתר.

חשבונית אוטומטית

הזמנת סוכן הנכנסת מממשק יכולה להפוך, באופן אוטומטי, לחשבונית מס. פעולה זו מתאימה ללקוחות שהמוצר שהם רוכשים אינו פריט מלאי ואין תהליך ליקוט, אריזה ומשלוח, כך שהמוצר סופק במלואו בזמן הרכישה באתר. אם רוצים לממש אופציה זו נדרשת תמיכה ממחלקת הטמעות.

פקודות יומן

באתרים מסויימים מפיקים חשבוניות מס וקבלות בתוכנות אחרות, ומעוניינים לממשק לחשבשבת אך ורק את נתוני פקודות היומן (הנהח"ש בלבד).אם רוצים לנהל את המלאי בחשבשבת, יש להעביר ממשק נוסף - של תנועות המלאי.
