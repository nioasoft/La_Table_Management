מפרט החישוב · החוזה

ההגדרה המחייבת. כל שינוי כאן מחייב עדכון של הבדיקות בשלב 1.

// ── קלט ───────────────────────────────────────────────────────
receipts            // סה"כ תקבולים מטאבית, כולל מע"מ
tips                // סה"כ טיפ מטאבית
includeTips         // franchisee.royaltyIncludeTips
tiers[]             // [{ upTo: number|null, rate: number }]   upTo כולל
tierBasis           // 'gross' | 'net'  ← באיזה בסיס הוקלדו הרפים
marketingRate       // franchisee.marketingFeeRate  (אחוזים)
discountRatePoints  // נקודות אחוז, 0 כברירת מחדל
vat                 // vat_rate.rate לתקופה, שבר. היום 0.18

// ── חישוב ─────────────────────────────────────────────────────
grossBase = receipts + (includeTips ? tips : 0)
netBase   = calculateNetFromGross(grossBase, vat)

// הרף מומר לברוטו, הבדיקה תמיד מול הברוטו
threshold(t) = tierBasis === 'net' ? t.upTo * (1 + vat) : t.upTo
tierRate     = tiers.find(t => t.upTo === null || grossBase <= threshold(t)).rate

effectiveRate = max(0, tierRate - discountRatePoints)

royaltyFull   = netBase * tierRate      / 100
royalty       = netBase * effectiveRate / 100
discountValue = royaltyFull - royalty
marketing     = netBase * marketingRate / 100

subtotal = royalty + marketing
total    = subtotal * (1 + vat)

ארבע נקודות שאסור לפספס במימוש

  1. הרף נבדק מול הברוטו, האחוז מוכפל בנטו. זה נראה כמו באג ולכן מישהו "יתקן" את זה. הנוסחאות של רעות מוכיחות: ויני חדרה, ינואר, ברוטו 739,638 בוחר 5%, והאחוז מוכפל בנטו 626,812 ומייצר 31,340. בדיקה על המקרה הזה, עם הערה בקוד.
  2. ההנחה נגרעת מהתעריף, לא מהסכום. netBase × (tierRate − points) ולא royalty × (1 − points). רק הראשונה מייצרת את קבצי החשבשבת של רעות.
  3. ההמרה של רף נטו קורית בזמן חישוב, לא בשמירה. החלטה 1 רף שנכתב בחוזה בנטו הוא רף תלוי-מע"מ. המרה בשמירה מקפיאה את שער היום לתוך הנתון, ובשנה שאחרי שינוי מע"מ הרף יהיה שגוי בלי שאף אחד נגע בו.
  4. אין עיגול. ה-מחיר בקבצי חשבשבת של רעות נושא 11 ספרות אחרי הנקודה (48228.82838983051). עמודות numeric(16,6), ייצוא של הערך כמו שהוא. roundAmount מ-file-processor.ts:95 אסור לשימוש כאן.

גבול המדרגה כולל. החלטה 6 upTo כולל, קונבנציה יחידה. באקסל של רעות מינה השתמשה ב-<= וויני וקינג ב-<, אבל מחזור שנוחת בדיוק על מספר עגול הוא מקרה שלא קורה, ואף אחת מ-37 השורות האמיתיות לא קרובה לגבול. במקום להוציא על זה מהקשב של רעות, המסך כותב "עד X (כולל)" ו"מעל X" במפורש.
